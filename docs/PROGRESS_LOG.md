## 2026-10-11 — 동일인 검사(웹 로그인 이름 = AWS 세션 이름), EC2 런북 실계정 확인
- 동일인 검사 구현(기본 꺼짐): 배포 `identityPolicy.requireLoginNameMatch`. 검증기가 서명된 로그인 이름(SAML bridge는 `name`, 외부 OIDC는 `loginNameClaim`)을 `loginName`으로 돌려주고, 호스트가 연결 binding에 서버 값으로 넣고(`bindingFor`), worker가 STS ARN 마지막 구간(Identity Center 사용자명)과 대소문자 무시로 비교해 다르면 `web_identity_mismatch`로 거부한다. 이름이 없으면 `web_login_name_missing`. 정책을 켜기 전 연결은 digest 불일치로 사용 불가(새 연결로 교체). 단위 테스트 7개 추가(226/226).
- 실계정(개인 테스트 계정, 웹 이메일과 AWS 사용자명이 같음): 정책을 켠 호스트에서 웹 로그인 → Payer 카드에서 한 번 클릭으로 Device Code → 승인 → 연결 성공, 동기화 성공. 거부 시나리오(웹 A, 승인 B)는 사용자가 한 명뿐이라 실계정에서는 하지 못했고 합성 테스트로만 확인했다.
- 결함 발견·수정: 호스트의 worker 승인 경로(`authorized()`)가 binding을 다시 만들 때 `loginName`을 빠뜨려 worker 생성 전에 거부됐다('전용 AWS 연결 환경을 시작하지 못했습니다'). 테스트가 이 경로를 다루지 않았다. 고치고 같은 경로 테스트를 추가했다.
- EC2 런북 실계정 확인: 테스트 인스턴스(t4g.nano 1대)를 만들어 중지·시작·재시작 런북을 요청→승인→실행했다. 중지(2회)·재시작·시작 모두 `Success`로 끝나고 인스턴스 상태가 `stopped`/`running`으로 바뀌었다. 첫 시작 실행은 직후 재시작 실행과 겹쳐 실패했다(재시작의 중지 단계가 시작 런북의 상태 검증과 충돌, 테스트 순서 문제). 겹치지 않게 다시 실행해 성공했다. 확인 뒤 인스턴스를 삭제했다(`terminated`, 남은 인스턴스·볼륨 없음). 런북이 실행 후 화면 상태를 읽는 데 시간이 걸려 '실행 중'이 잠시 남는 경우가 있다('상태 확인').
- 알게 된 점: `AWS-RestartEC2Instance`는 reboot가 아니라 중지 후 시작이다. 같은 인스턴스에 런북을 동시에 실행하지 않는다.
